# 30분 뒤에 비가 올까? — GK2A 초단기 강수 예측

천리안위성 2A호(GK2A) 적외 3채널로 **30분 뒤 강수 구간**을 예측하는 웹앱.

    U-Net 3개 (IR105 / WV063−IR105 / SW038−IR105)  ->  30분 뒤 위성 영상 예측
    LightGBM 구간 분류기 4개 (>=0.1, 1, 3, 10 mm/h) ->  지점 강수 구간

## 동작

1. 지역 검색(카카오 로컬 API) 또는 최근 목록에서 지점 선택
2. 기상청 API 허브에서 GK2A 3채널 × 과거 4프레임(30분 간격) = **.nc 12장** 수집
3. U-Net 3개(ONNX)로 30분 뒤 위성 영상 예측 → 특징 56개 조립
4. LightGBM 4개로 화소마다 구간 판정 + **단조성 보정**
5. 지도에 예측 구름·강수 구간 오버레이, 선택 지점의 구간을 표출

★ **"30분 뒤"는 마지막 관측 기준이지 '지금' 기준이 아니다.** 관측이 10분 격자이고
배포 지연이 약 8분이라 최신 프레임은 **8~18분 전**이고, 실제 리드타임은 **12~22분**이다.

### 성능 (2026년 독립 검증)

| 구간 | CSI | POD | FAR |
|---|---|---|---|
| ≥0.1 mm/h | 0.355 | 0.592 | 0.531 |
| ≥10 mm/h | 0.142 | 0.335 | 0.802 |

★ **강도 판별은 약하다.** 비가 오는지는 맞히지만 호우인지는 거의 못 맞힌다
(2026-07-20 ≥10mm/h POD 0.053). IR105 는 구름 정상 높이만 보므로 운정이 낮은
따뜻한 비·지형성 강수는 원리적으로 안 보인다.

## 로컬 실행

```bash
streamlit run app.py
```

인증키는 `~/.kmaapirc`(기상청)·`~/.kakaorc`(카카오)의 `key:` 뒤쪽을 읽는다.
키가 없으면 화면 확인용 더미 값으로 동작한다.

### 배포 경로 검증

```bash
python validate_vs_verify.py --npz ../runs/verify_20260720.npz
```

ONNX 추론이 검증된 원본(torch)과 같은 답을 내는지 화소 단위로 대조한다.
★ 합격 기준을 "최대 절대차 < 1e-5" 로 잡으면 안 된다 — 2단이 **트리 모델**이라
출력이 연속이 아니다. ONNX↔torch 의 1e-6 차이가 erode/dilate 에서 다른 화소를
뽑게 만들면 분기 문턱을 넘어 확률이 1e-2 **점프**한다. 대신 (1) 차이가 정확히 0 인
화소 비율 (2) 구간이 갈린 화소가 문턱 근처인지를 본다.
실측 — 7/20: cat 99.989% 일치(차이 0 이 99.945%) · 8/08: **100.000%**.

## Streamlit Community Cloud 배포

1. 이 `webapp/` 폴더를 **저장소 루트로** GitHub 에 올린다.
2. share.streamlit.io → New app → 저장소/브랜치 선택, Main file path `app.py`.
3. **Advanced settings 에서 Python 3.11 을 고른다.**
   `onnxruntime`·`netCDF4` 휠이 3.13 에 아직 안 올라와 있어 기본값이면 빌드가 깨진다.
4. Settings → Secrets 에 인증키 두 개:

   ```toml
   KMA_API_KEY    = "기상청_API허브_인증키"
   KAKAO_REST_KEY = "카카오_REST_API_키"
   ```

   ★ 인증키는 `.kmaapirc` 의 `key:` **뒤쪽만** 넣는다. 파일 전체를 붙여넣으면 안 된다.
   ★ 저장소에 키를 커밋하지 않는다 (`.gitignore` 에 `secrets.toml` 이 들어있다).

5. ★ **배포 URL 이 나오면 카카오 콘솔에 도메인으로 등록한다.** 안 하면 지역 검색이
   403 이다 — 키가 맞아도 로컬 API 는 앱에 서비스 도메인이 등록돼야 열린다.
   개발자 콘솔 → 앱 → 플랫폼 키 → REST API 키 → ⋮ → 수정.

## 손대기 전에 알아야 할 것

- **`inference.py` 의 특징 조립 순서를 바꾸지 마라.** 학습과 1비트라도 어긋나면
  예외 없이 조용히 틀린 값이 나온다. 고쳤으면 `validate_vs_verify.py` 를 돌릴 것.
- **`backend._grid()` 에 `@st.cache_data` 를 붙이지 마라.** 진행률 콜백이 함수 밖에서
  만든 `st.empty()` 에 그려서 "layout block created outside the function" 오류가 난다.
  모듈 전역 dict + Lock 을 쓰는 이유다. 락은 동시 접속 시 12장을 두 번 받는 것도 막는다.
- **Streamlit 은 임포트한 모듈을 다시 안 읽는다.** `backend.py` 등을 고치면 서버 재시작.
- **오류 메시지를 화면에 그대로 띄우지 마라.** `requests` 예외는 URL 전문을 담는데
  기상청은 `authKey` 를 쿼리스트링으로 받는다. `safe_msg()` 를 거칠 것.

## 시안과 다르게 간 부분

- **정량 mm/h 숫자를 안 띄운다.** 시안의 주인공은 58px 강수량 값 하나인데,
  2026 독립검증에서 비 표본 실측평균 4.00 → 예측평균 0.42mm/h(11%)로
  44mm/h 폭우에 1.7 을 냈다. 그 자리에 점 추정값 대신 **구간**("3–10")을 넣어
  시각 위계는 유지하되 없는 정밀도를 주장하지 않는다.
- **단계 기준이 시안(3/15/30 mm/h)이 아니라 학습된 구간(0.1/1/3/10)이다.**
  LightGBM 이 그 문턱으로 학습돼 있어, 표출 눈금을 바꾸면 모델이 실제로
  판별하는 것과 화면이 말하는 것이 어긋난다.
- **문구 강도를 구간에 맞춰 다시 썼다.** 시안 카피는 30mm/h 기준이라 최상위가
  "호우성 폭우"인데, 우리 최상위는 10mm/h 이상이라 과장이다. 기상청 강수 강도
  구분(약한 비 3 미만 / 보통 3~15 / 강한 15~30 / 매우 강한 30 이상)에 맞춰
  2·3·4단계 헤드라인·서브텍스트를 고치고 4단계 배지를 '호우 주의' → '우산 필수'로
  바꿨다. 구간 값 자체는 그대로다. 10+ 는 상한이 없어 진짜 호우도 들어오지만
  모델이 그걸 구분하지 못하므로(2026 검증 >=10mm/h POD 0.053) 화면이 구분하는
  척해선 안 된다.
- **검색 화면을 홈 안에 합쳤다.** 시안은 홈 → 검색 → 결과 세 화면인데 Streamlit 은
  풀스크린 전환이 어색하다. 검색은 홈에 인라인으로 두고 결과만 따로 뺐다.
  **홈에는 지도가 없다** — 지도는 결과 화면의 '레이더/위성 영상' 자리에만 있다.
- **비 애니메이션을 다시 만들었다.** 시안이 제시한 방식(반복 그라디언트 타일링)은
  모든 줄이 같은 길이·속도로 움직여 '움직이는 벽지'로 보인다. 물방울을 개별 요소로
  두고 속도(±25%)·길이·투명도를 제각각 줘서 깊이감을 만들었다. 낙하 시간 기준값
  (약한 1.9 / 보통 1.15 / 폭우 0.62초)만 시안에서 가져왔다.
  ★ 난수는 **고정 시드** — Streamlit 은 상호작용마다 스크립트를 다시 돌리므로
  매번 뽑으면 화면을 건드릴 때마다 비 배치가 튄다.
- **버튼 호버를 노랑 → 회색으로.** 시안에서 노랑은 '선택됨'을 뜻하는 색이라
  마우스만 올려도 노래지면 이미 고른 것처럼 읽힌다.
